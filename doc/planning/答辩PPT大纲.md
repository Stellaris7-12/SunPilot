## P09 方案调研④——为什么多Agent vs 单Agent

**布局：** 左侧"反对声音"，右侧"我们的3条理由"，底部数据支撑  
**背景：** 浅灰 `#F5F5F5`，章节标签 `02 方案调研`

**顶部——先承认争议（红色横幅，白字）：**
> ⚠️ **学术界存在争议：** arxiv 2606.13003《The Illusion of Multi-Agent Advantage》指出——  
> "并不是所有任务受益于多Agent，单模型能力足够时增加Agent数反而降低性能"

**左侧——单Agent"也可以"的声音（灰色背景，30%宽）：**
- LangChain官方：一个有正确工具和Prompt的单Agent通常能达到类似效果
- Nature 2026："能力饱和阈值"——模型足够强时多Agent无增益
- 单Agent架构：更简单，更低延迟，更少出错点

**右侧——我们场景的3条具体理由（白底卡片，70%宽）：**

```
① 上下文隔离
   ClassifierAgent只需场景模式识别 / ResolutionAgent只需工具Schema
   同一上下文窗口放5类知识=纯噪声
   研究：上下文隔离带来 1.1–12% 准确率提升（arxiv 2505.18286）

② 合规可审计性
   金融系统必须：字段是谁提取的 / 风险判定是哪步做的
   5个Agent = 5个独立审计节点，每步trace_steps完整记录
   单Agent推理过程是黑盒——金融合规不接受

③ 异构LLM配置
   业务Agent: DeepSeek网关（成本优化）
   PageAgent: 阿里/Qwen（页面理解优化）
   单Agent架构物理上无法实现分层LLM配置
   研究：异构配置带来最高 8.4% 性能提升（arxiv 2505.16997）
```

**底部——数据横幅（#CD2C42背景，白字，4个数字）：**

```
+1.1~12%         +8.4%           +90.2%           5个
多Agent准确率     异构LLM提升     Anthropic内部     独立审计
（MAS研究）       （异构研究）     多Agent提升       节点
```

> ↓ **Agent处理后（~3秒）**

> - 场景：`coupon_reissue`（优惠券补发）  
> - 优先级：P2

> - 回单话术：已生成，含结果+证据号+致歉语  
> - 状态：`PENDING_HUMAN_REVIEW`（等待坐席复核）

```
① Classifier     → 识别: coupon_reissue，P2，无高风险标记
② Intake         → 确定性快车道：5/5必填字段全部抽取（~0.3s）
③ Escalation     → 风险门控通过（非投诉/非争议/字段完整）→ can_auto_proceed=True
④ Resolution     → 工具规划: compensate_coupon → 校验 → Mock执行 → 返回成功
⑤ Notification   → 生成标准回单话术，closureSuggestion.canClose=True
```

> 👤 **系统进入 PENDING_HUMAN_REVIEW 状态**  
> 坐席查看：字段 · 工具执行证据 · 回单草稿 → **一键确认结案**
