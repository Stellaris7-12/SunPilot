# SunPilot —— 我做了什么 / 方案是什么 / 原理是什么

> 这三个是**不同的问题**，答辩时千万别混：
>
> | 问的是 | 判断标准 | 句式 |
> |---|---|---|
> | **① 我做了什么** | 你的交付物、工作量（可数、过去式） | "我**实现了** X" |
> | **② 方案是什么** | 系统的设计选择、长什么样 | "系统**采用** X" |
> | **③ 原理是什么** | 凭什么 work、为什么这么选（因果） | "**因为** A **所以** B" |
>
> 被问"你做了什么"→ 讲第一部分；问"你的架构/方案"→ 讲第二部分；问"原理/为什么"→ 讲第三部分。

|------|----------------------|--------------------|--------------------------|

## 第一部分：我做了什么（交付物）

> 回答"你的工作量是什么"。每条都是**可数的、你亲手产出的东西**，动词开头。

1. **搭建工单标准化管道**：把电话录音转写等非结构化数据还原为标准工单；基于 FastAPI
   构建异步处理服务与 SSE 流式接口，实现工单流转状态的实时推送。
2. **设计并实现多 Agent 编排框架**：手写 `PipelineContext` 编排器，串联分类、抽取、
   风险评估、执行、通知五个 Agent，解决多 Agent 协作的上下文传递与任务依赖。
3. **实现确定性优先 + LLM 兜底的抽取机制**：写了规则/正则快车道、LLM 慢车道，以及
   "LLM 只补空、不覆盖确定值"的合并逻辑（`_merge_fields`）。
4. **落地双轨制接入架构 + 语义化 PageAgent**：内部 API 直连 + 外部页面代填两条执行路径，
   PageAgent 通过前端语义接口无侵入操作。
5. **建全链路审计与人工闭环**：五个 Agent 节点独立 `trace` 留痕，状态机强制自动流程
   不可结案，结案唯一入口 `POST /api/tickets/{id}/close`。

> 简历/自述就用这 5 条。想压成 3-4 条：把 3 并进 2、把 5 的审计并进 4。

## 第二部分：方案是什么（设计）

> 回答"你的系统长什么样"。**不讲为什么，只讲结构**。

**总体：** 一条 5 Agent 线性流水线（Classifier → Intake → Escalation → Resolution →
Notification），两种执行轨道（API 直连 / PageAgent 代填），一个配置事实源
（`workflow_config.json`），全程 trace 留痕、人工结案。

**处理流程（真实执行序）：**
```
加载工单 → 高危短路? → [①分类 → ②抽取 → 字段补全 → ③风险闸门]
  → 停止判断(缺信息/待确认?) → ④工具规划+校验+执行 → 执行后复评 → ⑤结论 → 待人工审核
```

**三大设计选择：**
- **确定性优先**：能用规则解决的字段绝不动 LLM，LLM 只处理它擅长的非结构化缺口。
- **双轨制**：内部系统 API 直连（约 3s，全自动）；外部系统 PageAgent 代填（约 10s，人工确认）。
- **合规不可自动结案**：五节点独立审计，Notification 只出建议，人工 `POST /close` 才闭环。

## 第三部分：原理是什么（为什么成立）

> 回答"凭什么这样有效、为什么这么选"。**全是因果句**。

**① 为什么确定性优先 + LLM 兜底？**
因为 LLM 输出不稳定、不可复现，而金融场景要求可控可审计。所以身份证/金额/单号等
格式固定的字段用正则抽（结果稳定），LLM 只在必填字段缺口处补空，且**绝不覆盖已抽到的确定值**——
这样状态、证据、能否结案永远由确定性逻辑掌控。附带收益：required 全命中时 0 次业务 LLM 调用，快、省。

**② 为什么手写编排、不用 LangGraph/AutoGen？**
因为工单处理是严格的线性 DAG，没有复杂图状跳转需求。手写编排逻辑透明、可在每个节点插入
审计留痕、问题可精确定位，契合金融的确定性与可追溯诉求；用重框架反而是过度设计、增加锁定风险。

**③ 为什么要双轨制？**
因为内外部系统接入方式异构：内部系统有 API，直连最快；外部系统多数没有开放接口。
API 直连要求对方开接口、成本高；PageAgent 模拟页面操作零改造即可对接任意网页，
把自动化覆盖从"有接口的封闭系统"扩展到"全域网页系统"。

**④ 为什么 PageAgent 选语义化动作协议（而非纯视觉）？**
因为纯视觉方案要截图+LLM 解析坐标，延迟 2-5s、成本高、易被布局变化干扰。
自有前端可控，可主动暴露 `fillForm`/`submit` 等语义接口，Agent 直接调用 →
延迟降到亚秒级、成本低、稳定性高。外部不可控系统则退回 DOM 索引范式，故最终是**双范式混合**。

**⑤ 为什么自动流程不能自己结案？**
因为金融操作涉及资金安全，必须人把关、可追溯。所以自动化只做到"生成可否结案的建议"
（`closure_suggestion.can_close`），状态机卡在 `PENDING_HUMAN_REVIEW`，
真正关单必须人工经 `POST /close`——这是效率与合规之间的刻意取舍。
