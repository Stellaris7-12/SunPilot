# 工单系统分类体系总结

> 基于50张Demo截图的OCR提取 + 人工核验整理  
> 系统：招商银行信用卡「综合业务处理门户 FITS」

---

## 一、系统概览

该系统是一个**综合工单处理平台**，包含以下核心模块：

| 模块 | 说明 |
|------|------|
| **发单** | 创建/发起工单，含自动化发单(AUTOFDOI)和手动发单(CDKFFDOI) |
| **回单** | 处理工单并回复，含自动化回单 |
| **工单查询** | 综合查询、催收工单查询、处理工单查询、待处理工单查询 |
| **工单详情** | 查看工单详情、处理日志 |
| **派单设置** | 设置派单规则 |
| **工单转派** | 工单转派、多元工单转派、12378工单转派 |
| **工单报表** | 数据看板、名单发单量统计、回单逾期统计等 |
| **复核剔退** | 内部复核退单明细、外部退单统计 |

## 二、工单分类体系（一级 / 二级 / 细分）

### 按工单前缀编号规则

每种业务类型对应独立的工单编号前缀：

| 编号前缀 | 一级分类 | 二级分类 | 典型场景 |
|----------|----------|----------|----------|
| `11xxxx` | **协商还款** | 客助-协商还款 | 客户协商还款方案 |
| `12xxxx` | **伪冒** | 风险预防组 | 伪冒交易监控、客户两核身不过 |
| `13xxxx` | **伪冒** | 伪冒调查组 | 伪冒案件调查、案件进度查询 |
| `14xxxx` | **资管** | 查询欠款金额 | 欠款查询、资管通知 |
| `15xxxx` | **授权/授信** | 授权业务 / 授信业务 | 授权审批、额度管理 |
| `29xxxx` | **客户经营** | 个人金普卡业务 / AE百夫长卡 / 个人消费账户 | 客户维护、卡片服务 |
| `30xxxx` | **市场企划** | 饭票/影票/掌上生活/新品牌/品质电商 | 市场活动工单 |
| `38xxxx` | **客维** | 客维工单 | 客户维系 |
| `41xxxx` | **调单扣款** | 公司资料异动 | 交易调单 |
| `42xxxx` | **征信** | 贷后历史风险待确认 / E CODE | 征信查询确认 |
| `71xxxx` | **协商还款** | 协商还款 | 协商还款（另一种编号段） |

## 三、业务类型 vs 业务细分类型

在实际发单表单中，"业务类型"和"业务细分类型"是两个独立的下拉字段：

### 3.1 业务类型（一级）

| 业务类型 | 说明 |
|----------|------|
| 发卡作业疏失 | 发卡环节的疏失问题 |
| 年费优待调整 | 年费优惠政策调整 |
| 账务 | 账务相关问题 |
| 证件更改 | 客户证件信息变更 |
| 商务卡公司 | 商务卡/公司卡业务 |
| 汽车分期 | 汽车分期相关（如资料借阅、解抵押、结清证明） |
| 饭票/影票店面 | 餐饮/影票类商户（如总对总-麦当劳） |
| 调查类管制解管 | 调查类卡片管制解除 |
| 投诉引导 | 接受投诉引导 |
| 其他 | 兜底分类 |

### 3.2 业务细分类型（二级）

| 业务类型 | 对应细分 |
|----------|----------|
| 汽车分期 | 资料借阅及解抵押及汽车分期结清证明 |
| 饭票/影票店面 | 饭票总对总-麦当劳（等具体商户） |
| 调查类管制解管 | 其他 |
| - | AE运通百夫长卡 |
| - | 其他（兜底） |

## 四、发单表单关键字段

从截图中提取的发单/回单表单字段：

| 字段 | 说明 |
|------|------|
| 发单编号 | 系统自动生成 |
| 填表人姓名 | 当前用户 |

| 件别 | 一般件 / 紧急件 |
| 卡片列表 | 关联信用卡 |
| 卡片名称 / 备注 | 卡片信息 |
| **业务类型** | 下拉选择（见3.1） |
| **业务细分类型** | 下拉选择（见3.2） |
| 发单内容 | 自由文本 |
| 具体内容 | 详细描述 |
| 是否敏感 | 是/否 |
| 预警等级 | 风险等级 |
| 是否需要回复 | 是/否 |
| 补充信息 | 额外信息 |
| 规定回件日期 | 截止时间（SLA） |
| 接单单位 | 如「卡部 [上海卡部]」「市场 [020营销团队]」 |

## 七、复核剔退模块

专门处理工单的复核与退回：

- 自动化剔退（AUTOFDOI标记的自动发单若不符合规则会被自动剔退）
- 内部复核退单 → 明细统计
- 外部退单 → 明细统计
- 回单逾期件 → 逾期明细

## 八、设计建议

基于以上分析，工单系统的数据模型建议：

```
工单
├── 工单编号 (前缀区分业务线)
├── 一级分类: 征信/伪冒/授权/客户经营/资管/调单扣款/市场企划/客维/行销推广
├── 二级分类: 按前缀后2位进一步细分
├── 业务类型: 发卡作业疏失/年费优待/账务/证件更改/商务卡/汽车分期/饭影票/调查管制/投诉引导/其他
├── 业务细分类型: 具体业务场景
├── 发单信息: 发单中心/科室/部门/经办/日期/内容/附件
├── 回单信息: 回单经办/日期/内容
├── 客户信息: 客户号/姓名/证件号/手机号/账户
├── 状态流转: 待处理→处理中→已完成/已关闭
├── 紧急程度: 一般件/紧急件
├── SLA: 规定回件日期
├── 接单单位: 卡部/市场/客服...
└── 复核剔退: 内外部退单标记
```
